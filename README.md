# NetFlow/sFlow Traffic Monitoring System

Система мониторинга сетевого трафика на основе свободно распространяемых компонентов. Разработана в рамках выпускной квалификационной работы.

## О проекте

Система собирает метаданные о сетевых потоках по протоколам **NetFlow** и **sFlow**, агрегирует их, сохраняет в базу данных временных рядов и визуализирует через интерактивные дашборды с возможностью оповещений.

### Архитектура

```
Обычный трафик
      │
      ▼
┌─────────────┐   NetFlow/sFlow   ┌────────────┐
│   Сенсор    │ ────────────────► │ Коллектор  │
│  (pmacctd)  │                   │(nfacctd /  │
└─────────────┘                   │ sfacctd)   │
                                  └─────┬──────┘
                                        │ SQL
                                        ▼
                                  ┌────────────┐
                                  │ TimescaleDB│
                                  └─────┬──────┘
                                        │
                                        ▼
                                  ┌────────────┐
                                  │  Grafana   │
                                  │ (dashboards│
                                  │  + alerts) │
                                  └────────────┘
```

### Компоненты

| Компонент | Реализация | Назначение |
|-----------|------------|------------|
| **Сенсор** | `pmacctd` (плагины `nfprobe`, `sfprobe`) | Захват трафика и экспорт в NetFlow/sFlow |
| **Коллекторы** | `nfacctd`, `sfacctd` | Приём, агрегация, запись в БД |
| **Хранилище** | TimescaleDB (PostgreSQL) | Хранение flow-записей (гипертаблица) |
| **Визуализация** | Grafana | Дашборды, алерты |

## Быстрый старт

### Требования

- Docker и Docker Compose
- Linux (тестировалось на Ubuntu 22.04)
- 4 vCPU, 8 ГБ RAM (рекомендуется)

### Установка

```bash
# 1. Клонировать репозиторий
git clone https://github.com/Zdorovets-Mark/netflow-sflow-monitoring.git
cd netflow-sflow-monitoring/docker_stack

# 2. Скопировать шаблон переменных окружения
cp .env.example .env

# 3. Отредактировать .env — вписать свои параметры (пароли, SMTP для алертов)
nano .env

# 4. Запустить стек
docker-compose up -d

# 5. Проверить статус
docker ps
```

После запуска:

- **Grafana:** http://localhost:3000 (логин `admin`, пароль из `.env`)
- **TimescaleDB:** `localhost:5432`
- **Коллекторы:** UDP `2055` (NetFlow), `6343` (sFlow)

### Проверка работы

```bash
# Логи сенсора
docker logs -f nfprobe
docker logs -f sfprobe

# Логи коллекторов
docker logs -f nfacctd
docker logs -f sfacctd

# Проверка записей в БД
docker exec -it timescaledb psql -U postgres -c "SELECT COUNT(*) FROM netflow_data;"
```

## Результаты тестирования

Нагрузочное тестирование TimescaleDB (10 млн записей):

| Метрика | Значение |
|---------|----------|
| Скорость вставки | >2200 записей/с |
| Q1 — сумма байт за час | 0,003 с |
| Q2 — топ-10 источников за день | 0,217 с |
| Q3 — распределение по протоколам | 0,001 с |
| Q4 — минутный трафик | 0,004 с |
| Размер БД | 926 МБ |

Сравнение с альтернативами показало, что TimescaleDB обеспечивает лучший баланс между скоростью вставки, производительностью запросов и компактностью хранения.

## Генерация тестового трафика

```bash
# Генерация pcap через Python
python3 scripts/gen.py

# Воспроизведение с заданной скоростью
sudo tcpreplay -i enp0s9 --preload-pcap --pps=50000 traffic.pcap
```

## Стек технологий

- **Docker / Docker Compose** — контейнеризация и оркестрация
- **pmacct** (`pmacctd`, `nfacctd`, `sfacctd`) — сенсор и коллекторы
- **TimescaleDB** — база данных временных рядов
- **Grafana** — визуализация и алертинг
- **Python** — генерация тестовых данных
- **NetFlow, sFlow, IPFIX** — протоколы сбора метаданных

## Особенности реализации

- **Автоматизация развёртывания** — весь стек поднимается одной командой `docker-compose up -d`
- **Provisioning Grafana** — дашборды, источники данных и алерты загружаются автоматически из YAML/JSON
- **Изоляция секретов** — все пароли и ключи вынесены в `.env` (не попадают в репозиторий)
- **Гипертаблица TimescaleDB** — автоматическое секционирование по времени с интервалом 1 день
- **Алерты** — оповещения при отсутствии данных от сенсора и превышении порогов трафика

## Ограничения

- Тестирование проводилось в виртуальной среде (VirtualBox)
- Поля `iface_in` / `iface_out` остаются нулевыми из-за особенностей программного сенсора на libpcap
- Безопасность (шифрование каналов, аутентификация) не реализована — предполагается изолированная сеть
- Нагрузочное тестирование сенсоров ограничено возможностями виртуальной среды (режим «черепахи» в VirtualBox).
